Observed on user's Windows: sing-box 1.14.4 reported unable to update bind: listen udp6 [::]:60880: An invalid argument was supplied; then failed to send handshake initiation: address family not supported by protocol. No WireGuard handshake was present on NYC1 and no UDP packets were recorded by its capture. The local socket error explains the missing handshake; end-to-end UDP remains unverified.

Change: Get-HybridConfig now assigns the WireGuard endpoint detour=wg-transport. This dedicated direct outbound has inet4_bind_address=0.0.0.0. There is exactly one literal IPv4 server peer and no explicit listen_port. No application routing rule targets wg-transport. Application UDP still targets udp-exit, TCP still targets Tor, DNS still uses TCP through Tor. The existing global auto_detect_interface and server /32 TUN route exclusion remain. No Windows IPv6 binding, system file, guard binary, server config or key changes are made.

Pinned v1.14.4 source was checked: transport/wireguard/endpoint.go selects standard bind for a dialer implementing UDPListener, otherwise ClientBind. A DetourDialer to protocol/direct.Outbound does not expose UDPListener through that outbound. With one literal peer ClientBind.connect uses DialContext to that IPv4 endpoint, avoiding the failed udp6 listener.
