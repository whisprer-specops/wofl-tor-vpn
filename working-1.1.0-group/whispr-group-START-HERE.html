What the group does

Your group has a shared list of VPN exit servers. Each person chooses one exit for their own connection. A member can use the group without owning a server. Anyone contributing a server keeps control of their own SSH account and approves the devices that can use their server.

This version shares Internet exit choices; it does not create a shared LAN between members' PCs. It does not bond servers together or multiply one person's connection speed. The existing hybrid transport is retained: UDP uses the selected WireGuard VPS exit; TCP/DNS follow the client's Tor path. Choosing a city does not put every protocol through that city's VPS.

There are two public files to recognise:

  • friend-request.json: one PC asking to join. The filename is retained for compatibility. It contains a public key, a fingerprint and the device's name.
  • group.json: the current member list and published endpoints. This is the file you pass around after membership or server updates.

Nobody shares their private device key or their SSH login. Members exchange these files through a trusted direct conversation. Group files are validated but are not digitally signed; check who sent the file. Members must trust the people running an exit, just as with any VPN provider.

Before starting

  1. Download the appropriate ZIP and choose Extract All. Work in the extracted folder, not inside the ZIP preview. Keep the folder somewhere writable, such as Documents. Do not put the group tools under Program Files.
  2. Disconnect other VPNs while testing whispr. If using Proton, turn its kill switch off (including Advanced Kill Switch), disconnect it, then quit it. Proton may remain installed.
  3. On a PC already using whispr, select Disconnect / Recover, then Close tray only before importing or publishing group changes. These operations require the tunnel to be disconnected; the tools do not silently disable protection.
  4. Windows administrator approval is required. The tools use PowerShell already bundled with the installed MSI; a separate PowerShell installation is unnecessary.

The installer is unsigned. Obtain the ZIP directly from someone you trust. If Windows marks the download as blocked, open the ZIP's Properties, choose Unblock if present, Apply, then extract it again. Do not disable Windows security.

A. New member — join someone else's group

A1. Install whispr once

In the full Windows ZIP, double-click INSTALL-WHISPR.cmd. Read/accept the license and finish the MSI installer. If Windows offers maintenance for an existing copy, use Repair only if repair is needed; an already working copy can simply use OPEN-GROUP.cmd instead.

A fresh PC needs Internet access because the installer downloads and verifies its pinned Tor bundle. No server password or device identity is included in the ZIP. If installation fails, retain the log named whispr-group-install.log in the Windows temporary folder. The installer launcher reports the location.

A2. Make your public join request

Double-click OPEN-GROUP.cmd and accept the administrator prompt.

Choose 1 — Make MY public membership request. Enter a short device name such as Alice-Laptop. The tool creates a private identity on this PC if it does not already have one. Repeating this step keeps the same identity.

Open the tool folder's share subfolder and send friend-request.json to the group organiser. Then wait for them to return group.json. You do not need SSH or a VPS account to be an ordinary member.

Do not choose “Create a NEW group”. Your organiser creates the group once.

A3. Import your access and connect

Save the received group.json somewhere you can find it. In OPEN-GROUP choose 2 — Import the group.json I received, then select that file.

A successful import reports how many shared exits are approved for this PC. If it reports zero, your organiser/VPS owners have not yet published your access. Ask for the updated group.json after they sync; do not generate another identity.

Choose 3 — Open the VPN tray. Choose an approved exit, then Connect. Green means the client's live transport verification passed. You can later open whispr from the Windows Start menu normally.

That completes joining. Read section C only if you also want to contribute a VPS.

B. You — start the group and admit members

B1. Open the manager kit

Your tested MSI is already installed. Extract the manager ZIP and double-click OPEN-GROUP.cmd. Disconnect / Recover whispr and close its tray first.

Choose 4 — Create a NEW group. Enter a group name and a name for your device. Do this once. It creates group.json in your tools folder.

If your existing exit profiles belong to this device, their known SSH aliases and locations are copied into my-vps.json automatically. The number shown is the number found on your PC; an unprepared exit is not automatically provisioned.

If the tool says you already have a catalogue, use 9 — Recover/export instead of creating another group. Keep your existing group identity.

B2. Add the people who sent requests

For each received friend-request.json, choose 5 — Add a received member request and select that person's file. Each laptop/PC is a separate device and needs its own request. Rename downloaded requests for your convenience if several have the same filename; the file's contents identify the device.

Adding a request changes the roster. It does not yet grant access on any VPS.

B3. Publish your servers

Choose 7 — Publish / sync MY VPSs. Read the displayed device names and public fingerprints. Type YES only if those are the members you intend to approve.

Leave the window open while it processes your listed servers. It may ask for each server's sudo password; that password goes to your own server, not to group members. Your existing managed exits retain their server keys and listener/firewall setup; the publishing operation synchronises group peers. A new exit needs the server setup described in section C.

When the operation completes successfully, send the updated group.json from your tools folder to every member. Your own approved profiles are imported too. Choose 3 to reopen the VPN tray when you are ready to reconnect.

B4. When another person contributes a server

Receive their updated group.json, disconnect/close the tray, then choose 2 — Import. You and the other members can then choose their newly approved server. Nobody needs that person's SSH private key or server password.

C. Contribute one of your own VPSs

Join/import the existing group first. You need a VPS that you administer, with a public IPv4 address, supported Ubuntu/Debian Linux, root or sudo access, and working key-based OpenSSH from your Windows PC. The publishing tool requires SSH and SCP.

A home Windows PC behind NAT is not an exit server in this release. There is no automatic residential NAT traversal or Windows endpoint-hosting installer here.

C1. Check your own SSH access

Use your existing Windows SSH alias for this server. An alias is the short name in your own SSH config; it is never sent to other members. A configured alias is required for custom SSH ports, identities or usernames. Direct user@IPv4 on port 22 is also supported. The resolved host must be a literal public IPv4 address.

In PowerShell, this interactive check accepts your real alias:

$myExitAlias = Read-Host 'Your existing SSH alias, or user@public-IPv4'
ssh $myExitAlias

Verify the server's SSH host-key fingerprint through your VPS provider before accepting a first connection. Type exit to return to Windows. Next confirm that key-based login works without an account-password prompt:

ssh -o BatchMode=yes -o StrictHostKeyChecking=yes $myExitAlias 'id -un'

If your SSH key has a passphrase, unlock it through your existing SSH agent first. Resolve a failed login/unknown host key before publishing. The tool does not switch off host-key checking or share/store SSH passwords. If ssh/scp are missing, install Windows' OpenSSH Client optional feature first; ordinary members do not need it.

C2. Add the server to your local list

In OPEN-GROUP choose 6 — Add one of MY VPSs. Enter your SSH alias, a useful server name and location. The city chooser can fill coordinates; custom latitude and longitude are supported. The usual WireGuard port is UDP 51832.

This writes your local my-vps.json. It does not configure the remote server yet. Use only servers you administer. Your account must be able to use sudo if not root.

C3. Allow the VPN port at your provider

If the VPS has a provider/cloud firewall, allow inbound UDP 51832 (or the UDP port you chose). TCP 51832 is not the same rule. Keep your existing SSH rule. If restricting source addresses, include each member's current public Internet IP. If members use changing/mobile addresses, you must maintain that restriction or allow the UDP listener from all IPv4 addresses. WireGuard still requires approved keys. Do not remove unrelated firewall rules or open unrelated ports.

C4. Publish and return the updated file

Disconnect / Recover whispr and close its tray. Choose 7 — Publish / sync MY VPSs, review the roster, type YES, and answer your own server's sudo prompt if needed.

For a new compatible exit, the tool sets up the dedicated wg-whispr interface, scoped forwarding/NAT and reboot service. It refuses unmanaged/conflicting network configuration. Existing unrelated tunnels/services are not its cleanup targets. Do not force a failed preflight by deleting another application's interface.

After success, send the resulting group.json to the others. They import it with menu 2. Test a real connection through the new exit; a successful server configuration message alone is not proof that UDP is reachable from a member.

D. Keeping the group in step

Add another member later

  1. They use menu 1 and send their public request.
  2. You use menu 5 to add it, then send the updated group.json to all VPS owners.
  3. Each VPS owner imports the current file and runs menu 7 on their own servers.
  4. Pass the updated file between owners in order, so each starts from the latest copy. Send the final updated file to members for menu 2.

There is no central always-on sync service. Publish access only after reviewing that roster. The group supports up to 64 device identities and 128 published exits.

Remove a guest device

Choose menu 8 on a current group file. Distribute that updated file to every VPS owner. Access is revoked only after every relevant owner has synced menu 7. A client-side import or deleting a local file cannot revoke remote WireGuard access.

Contributing owners cannot be removed with the guest shortcut while their exits remain published. Automated exit retirement/server-key rotation is outside this version. Removing a row from my-vps.json does not decommission that server.

Keep one current working folder

Your folder contains your current group.json, your local my-vps.json, and operation receipts under results. Keep it rather than re-extracting over it. If moving to another tools folder, retain those two JSON files; never overwrite a populated my-vps.json with the empty template from the ZIP.

If you lose group.json but have previously imported/published it, menu 9 exports your stored catalogue. If creation was never imported/published, recover the working file from your backup or another member instead. Do not create a new GroupId to work around a lost file or stale-revision error.

F. Repair and uninstall

Run the supplied MSI again for Repair or Uninstall, or use Windows Installed Apps. Repair keeps the local identity/profiles. Uninstall deletes this app's local identity/state and owned tasks; it does not revoke your public key on remote VPSs. For permanent departure, arrange group removal/sync first. Uninstalling and then installing fresh creates a new device identity which must be admitted again.

The external group-tools folder is a separate portable management workspace. MSI uninstall does not delete it. Delete it yourself when no longer needed, after retaining or handing over any current public group file you still need.

Never send: device-key.json, engine.json, SSH private keys, server passwords or a complete copy of ProgramData\whispr-hybrid. Only the original clean install ZIP, public join requests and the current group.json are intended for distribution.

Verification boundary

The included MSI is byte-for-byte the build the original user confirmed working. Group protocol/client/server tests and fresh-member onboarding tests are executed for this packaging release; see VERIFICATION.md for actual results. No live remote server is changed while building the ZIPs. Multi-PC Windows/group network acceptance must still be established by connecting the first pair of devices. No bundled test result substitutes for that real connection check.
